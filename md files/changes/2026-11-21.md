
## Dashboard summary cards: pending count as main figure, total as subtext

**Files modified**
- `client/src/pages/DashboardPage.tsx`

**What / why**
All seven Overview tiles now show the *pending* count as the large number and the total as subtext (`N total`), replacing the date subtext.
- Event tiles (Today / Tomorrow / This Week / This Month / Upcoming): pending = order status `YET_TO_START` or `IN_PROGRESS` (not `ORDER_CLOSED` / `REJECTED`), counted from the calendar / events-report data already loaded.
- Appointment tiles: pending = the Enquiry list's existing `APPOINTMENT_PENDING` group (appointment status Pending or In Progress, excluding drafts and lost enquiries). Two extra small count queries were added; the tiles now drill down with `view=APPOINTMENT_PENDING` so the number matches the list.

**Database changes**: None
**API changes**: None (existing endpoints; `statusGroup` filter reused)

**Follow-up notes**
- "Pending event" is not defined in the project docs; the definition above is an assumption, so confirm it. Changing it is one constant (`PENDING_EVENT_STATUSES`).
- Event tiles still drill down to the full calendar/report for the period, which lists all events, not only pending ones.
- Dates were removed from the tile subtext (labels already name the period). Not verified in a browser; `tsc --noEmit` only.

## Orders list: status-based counts in card subtext (supersedes the pending-fields change above)

**Files modified**
- `server/src/modules/orders/{repository,types}.ts`
- `client/src/types/order.ts`
- `client/src/pages/orders/OrderListPage.tsx`

**What / why**
Each Orders summary card (Total, Today, Tomorrow, This Week, This Month) keeps the pending count as its main figure and now lists, in its subtext: `N total`, `x Yet To Start · y In Progress`, `z Closed · w Rejected`. Pending = Yet To Start + In Progress. The server now groups counts by status per scope (5 `groupBy` queries) instead of the previous 11 count queries, and derives the existing totals from them. The interim `pending` / `*EventsPending` response fields added earlier today are removed (never released).

**Database changes**: None

**API changes**
- `GET /api/orders/stats` — existing fields (`total`, `todayEvents`, `tomorrowEvents`, `thisWeekEvents`, `thisMonthEvents`, `closed`) unchanged. New `byStatus: { total, today, tomorrow, thisWeek, thisMonth }`, each `{ yetToStart, inProgress, closed, rejected }`.

**Follow-up notes**: Cards are now three subtext lines tall, so the row is taller and long lines truncate on narrow tiles. Subtext stays hidden on phone width. Dashboard Overview tiles were not changed. Not verified in a browser.

## Reports: month-wise tables for Revenue, Outstanding and Expenses

**Files created**
- `client/src/pages/reports/MonthlyReportTable.tsx` (shared month-wise panel)
- `client/src/pages/reports/monthLabel.ts` (shared `YYYY-MM` → "Nov 2026"; `null` → "No event date")

**Files modified**
- `server/src/modules/reports/{repository,service}.ts`
- `client/src/types/report.ts`
- `client/src/pages/reports/tabs/{RevenueReportTab,OutstandingReportTab,ExpenseReportTab}.tsx`

**What / why**
Each of the three reports now has a month-by-month table, with CSV export, beside its existing charts/list, and it follows the report's own filters:
- **Revenue** — "Monthly Revenue": month, payments, revenue collected (by payment date). Uses the monthly data the API already returned.
- **Outstanding** — "Monthly Outstanding": event month, orders, total, paid, outstanding. New server query; orders with no event date appear in a "No event date" row so the months always add up to the total outstanding.
- **Expenses** — "Monthly Expenses": month, expense count, total. Uses the existing month trend; shown on the Reports page only (the Dashboard's Duration view can group by day/week).
The month-label helper moved out of `RevenueReportTab` into the shared file.

**Database changes**: None

**API changes**
- `GET /api/reports/outstanding` — `summary` gains `monthly: [{ month: "YYYY-MM" | null, orderCount, totalAmount, paidAmount, pendingAmount }]`, oldest first, no-date last. Existing fields unchanged.

**Follow-up notes**
- Verified the new SQL against the dev database: monthly rows sum to the report total (42 orders / 4,316,670).
- The API must be restarted (it runs `dist/`, which was rebuilt) for Outstanding's table to populate.
- Revenue is bucketed by payment date and Outstanding by event date — the same lenses each report already uses. Not verified in a browser.

## Reports: Revenue, Outstanding and Expenses default to the current month, with a Yearly view

**Files created**
- `client/src/pages/reports/useReportPeriod.ts` (month / year period state → date window + trend granularity)
- `client/src/pages/reports/PeriodFilter.tsx` (View dropdown: Monthly / Yearly, plus month or year picker)

**Files modified**
- `client/src/pages/reports/tabs/{RevenueReportTab,OutstandingReportTab,ExpenseReportTab}.tsx`

**What / why**
On the Reports page these three tabs no longer use free-form Date From / Date To. They show **one calendar month — the current month by default** — and the **View** dropdown switches to **Yearly** (year picker, current year by default). Event Type / Customer / Category filters are unchanged. Clear returns to the current month.
- Revenue: payments, method breakdown and the payment list are for the chosen month/year. Revenue and the order position keep their existing lenses (payment date vs event date).
- Outstanding: orders with a balance whose event falls in the chosen month/year.
- Expenses: a month's trend is drawn day by day (every day shown, including zero days); a year's month by month.
- The "Monthly Revenue / Outstanding / Expenses" tables added earlier today now appear only in the Yearly view, where they have more than one row.
The Dashboard's Expenses graph (Duration dropdown) is unchanged.

**Database changes**: None
**API changes**: None (this change only varies the existing dateFrom/dateTo/granularity parameters).

**Follow-up notes**
- A past month's report is no longer reachable as a free date range (e.g. 15 Oct – 20 Nov); only whole months and years. Say if a custom range option is also wanted.
- "Revenue by Month" chart shows a single bar in the Monthly view, as the API always buckets that chart by month.
- Not verified in a browser.
