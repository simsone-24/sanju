## Quotations: multi-delete and a separate Delete action on the list

- **Files modified:**
  - Server: `server/src/modules/quotations/{routes,controller,service,repository,validation,types}.ts`, `server/src/modules/orders/repository.ts`
  - Client: `client/src/components/DataTable.tsx`, `client/src/pages/quotations/QuotationListPage.tsx`, `client/src/pages/quotations/quotationStatusTransitions.ts`, `client/src/services/quotationService.ts`
- **What/why:**
  - Quotation list rows get a red Delete icon in the Actions column (moved out of the ⋮ menu). It's disabled for Approved quotations, with a hint.
  - Rows can be ticked (checkbox column, select-all for the page). A "N selected" bar offers Clear selection and Delete selected; the confirm dialog lists the quotation numbers and shows any refusal inside it.
  - For an enquiry row, the revision shown (the latest) is the one deleted, same as the single delete.
  - The selection is keyed by quotation id and resets when the page, page size or any filter changes.
  - `DataTable` gained an optional `selection` prop (opt-in; other tables unchanged).
  - Server: single and bulk delete share one rule check (`findDeleteBlock`) and one soft-delete + enquiry-summary sync helper. `softDeleteQuotation` became `softDeleteQuotations` (one `updateMany`).
- **Database changes:** None
- **API changes:**
  - `POST /api/v1/quotations/bulk-delete` (QUOTATIONS → Delete). Body `{ "ids": number[] }` (1–100). Success `200 { success, message: "N quotations deleted successfully.", data: { deletedCount } }`.
  - All or nothing. `404` if any id is missing or already deleted. `400` if any is blocked (order raised from it, or Approved): `message` "Nothing was deleted. These N quotations can't be deleted:", `errors: [{ field: "<number> (v<version>)", message: "<reason>" }]`.
  - Each deleted quotation gets its own `DELETE` activity-log entry.
- **Notes:** Deleted quotations stay restorable from Audit Log → Deleted Items.

## Permissions: Dashboard Reports under Dashboard; one permission per Reports tab

- **Files created:** `client/src/constants/reportPermissions.ts`, `database/2026-11-24/01_split_report_permissions.sql`, `server/prisma/migrations/20261124000000_split_report_permissions/migration.sql`
- **Files modified:** `server/src/modules/permissions/catalog.ts`, `server/src/modules/reports/routes.ts`, `server/prisma/seed.ts`, `client/src/types/permission.ts`, `client/src/layouts/AppLayout.tsx`, `client/src/pages/reports/ReportsPage.tsx`, `client/src/pages/DashboardPage.tsx`, `client/src/pages/dashboard/DashboardReports.tsx`
- **What/why:**
  - The separate "Dashboard Reports" module is gone; it is now a **Reports** checkbox inside the **Dashboard** card (`DASHBOARD.canViewReports`).
  - The **Reports** card's single View is replaced by one checkbox per tab: Revenue, Outstanding, Customers, Orders, Expenses (`canViewRevenueReport`, `canViewOutstandingReport`, `canViewCustomerReport`, `canViewOrderReport`, `canViewExpenseReport`), plus Export as before.
  - The Reports page shows only granted tabs; it and its sidebar entry appear when any tab is granted. The Orders and Expenses tabs still also need Orders / Expenses View.
- **Database changes:** Data only (no schema change): `database/2026-11-24/01_split_report_permissions.sql`. It converts existing grants so nobody gains or loses access (Reports View → all five tabs; Dashboard Reports or Reports View → Dashboard Reports) and removes the old rows, for groups and user overrides. Applied to the local DB.
- **API changes:**
  - `GET /reports/revenue`, `/outstanding` and `/customers` now need their own tab permission.
  - `GET /reports/orders` and `/expenses` need the tab permission or `DASHBOARD.canViewReports`, plus Orders / Expenses View.
  - `GET /reports/events` (used only by the Dashboard's upcoming-events tile) now needs `CALENDAR.canView`, like the Dashboard's other event tiles.
  - The permission catalog response changes accordingly.
- **Notes:** The live server needs this SQL file run when the new code is deployed. Until then its groups have no Reports tabs and no Dashboard Reports.
