
## Self-service user profile (edit details, photo, password)

**Files created**
- `client/src/pages/profile/ProfileDialog.tsx`
- `client/src/validation/profileSchemas.ts`
- `client/src/hooks/useProfilePhotoUrl.ts`

**Files modified**

- `server/src/modules/users/validation.ts` (field schemas exported for reuse)
- `client/src/services/authService.ts`
- `client/src/layouts/AppLayout.tsx` ("My Profile" row in the account panel; profile photo on the sidebar avatar)

**What / why**
Editing a user previously required Masters → Users permission, so ordinary users could not correct their own details. Signed-in users can now update their own name, mobile, email, city and photo, and change their password (current password required). Username, user group, active flag and permissions remain administrator-only. Email uniqueness is enforced; changes are written to the activity log.

**Database changes**: None

**API changes** (all authenticated, act on the caller only; no Masters permission)
- `PUT /api/auth/profile` — `{ fullName?, mobile?, email?, city? }` → updated profile
- `POST /api/auth/profile/photo` — multipart `photo` (jpeg/png/webp, max 2MB) → updated profile
- `GET /api/auth/profile/photo` — returns the caller's own photo file
- `PUT /api/auth/password` — `{ currentPassword, newPassword, confirmPassword }` → `null`

**Follow-up notes**
- Changing a password does not invalidate existing refresh tokens (no token revocation exists yet).
- A replaced profile photo file is not deleted from disk (same as the existing admin upload).
- The project has no ESLint config; only `tsc --noEmit` was run (server and client, both clean). Not exercised in a browser.
